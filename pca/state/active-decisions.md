# Active Decisions

- The commercial offer is positioned as an installed sales system for medium-high/high-ticket service businesses already running lead-generation campaigns, not as an n8n product.
- Lead forms must explicitly authorize evaluation and contact through WhatsApp or email, link to `/privacidad`, and be rejected server-side without consent.
- Marketing copy must not guarantee leads, sales, revenue, ROAS, or specific results; Ads management is outside the implementation scope unless separately agreed.
- Qualified implementation requests are persisted in PostgreSQL before sending a Telegram alert; Telegram failures must not discard the persisted lead.
- Telegram credentials remain private Railway variables and must never be committed, logged, or exposed in frontend code.
- n8n projects live under root `modules/`; the root `AGENTS.md` defines global context, `modules/AGENTS.md` defines shared n8n conventions, and each module may add a more specific `AGENTS.md`.
- The current commercial horizontal is Telegram, not WhatsApp. Google Ads is the initial paid acquisition channel; Telegram Ads is excluded because it requires TON/wallet funding and adds unnecessary launch friction.
- Initial market grouping: trading communities, forex communities, and financial-education communities. Gambling/betting is excluded from the public paid offer because of platform-policy and compliance risk.
- The offer is framed around measurable improvement in manual hours, operational capacity, qualified conversations, attendance, follow-up, or conversion process. No solution is built if it cannot define a before/after metric.
- The landing headline and copy should speak to the operator's lived problem: messages, questions, classes, and requests mixed in one Telegram chat, with no reliable next step.
- The word Telegram is the primary visual accent and uses a strong blue; green is not the horizontal brand color.
- Pricing is displayed as the real offer only (for example, "Desde US$300"). Do not use crossed-out prices, "precio de referencia", artificial anchors, scarcity, or fake discounts.
- Current architecture direction: a modular monolith with a shared FastAPI core for tenancy, leads, conversations, tracking, metrics, jobs, security, and integrations; vertical-specific domain code lives under `backend/app/verticals/<vertical>/`, and n8n workflows under `modules/<vertical>/`.
- Production validation uses GTM `GTM-N8HLK7MP` with GA4 `G-E7NYCYLRX`; the published container tracks `view_landing`, `submit_implementation_request`, `view_implementation_success`, and `click_telegram_implementation`.
- The production landing is `https://quantsystems.thequantpartners.com/`; the FastAPI backend is on Railway at `https://backend-production-3a7f.up.railway.app`.
- Qualified leads are stored before notification. The active alert bot is `@quantsystemss_bot`, and its private chat destination is configured only in Railway.
- Telegram Bot API supports HTML/Markdown formatting, inline URL buttons, callback buttons, commands, and Web Apps. The current alert sends plain text; interactive alert buttons are a future enhancement, not required for the Ads launch.
- Google Ads authentication is operational through manager `3160406729` and child account `4433232603`; the MCP is used for reporting/discovery, while the installed preset tools have opaque errors for some child-account queries and do not expose campaign creation operations.
- The production landing's primary integration section lists ten high-adoption platforms with real API/webhook/OAuth surfaces: Shopify, WooCommerce, Odoo, HubSpot, Salesforce, Google Workspace, Mercado Pago, Stripe, Google Ads, and Calendly. Odoo integration requires an eligible plan with external API access; all integrations remain subject to the client's product, plan, permissions, and exposed events.
- Platform names are rendered as lightweight text wordmarks rather than external logo images to preserve landing performance and avoid unnecessary asset/licensing dependencies.
- The final landing disclaimer uses concise independent-service language: Quant Systems is not Telegram or affiliated with it, does not provide financial advice/signals/investment recommendations, and does not guarantee revenue, sales, ROI, or specific results.
- End-to-end QA on 2026-08-14 used synthetic QA data with test UTMs/GCLID. Railway returned HTTP 201 from `/api/v1/implementation-requests`, persisted lead `2f838d80-836b-4f9d-9d66-3a0884f10ffc`, returned `created=true` and `notification_sent=true`, and the landing emitted `submit_implementation_request` and `view_implementation_success`. The test used no real customer data and no Ads campaign was activated.
